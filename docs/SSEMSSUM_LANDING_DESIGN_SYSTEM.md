# 쌤씀 서비스 랜딩 · 기획 및 디자인 시스템 v1.3

> 목적: 완성된 쌤씀 서비스를 처음 보는 교사가 무엇을 할 수 있는지 빠르게 이해하고, 실제 제품 화면을 확인한 뒤 시작하도록 돕는다. MVP 모집·사전 신청 페이지가 아니다.
>
> 기준 자료: 쌤씀 Figma 프로토타입, 기존 뽀뽀 MVP 사이트, 공유된 사업 자료와 교사 조사, 대화에서 확정한 브랜드 취향. 이 문서는 랜딩 제작의 기준이며 실제 제공 범위·가입 주소·법적 고지 문구는 공개 전 제품 정보와 대조한다.

## 1. 한눈에 보는 방향

| 항목 | 결정 |
| --- | --- |
| 서비스 정의 | 사진과 메모를 바탕으로 교사의 보육 기록 초안을 돕는 서비스 |
| 핵심 문장 | **선생님이 쓰는 보육비서, 쌤씀** |
| 첫 화면 제목 | **선생님의 오늘이, 기록의 초안이 되도록.** |
| 첫 화면 설명 | 사진이나 메모로 오늘의 기록을 시작하세요. 알림장에서 관찰일지까지, 보육일지에서 주제계획안까지 초안을 이어 만들고 선생님이 확인·수정합니다. |
| 주요 행동 | **쌤씀 체험하기**. 가입 없이 사용할 수 있는 체험 화면으로 바로 연결 |
| 보조 행동 | **어떻게 쓰는지 보기**. 첫 사용 흐름 섹션으로 이동 |
| 가장 앞세울 강점 | 사진과 메모로 기록 초안을 쉽게 시작하는 경험 |
| 랜딩 형식 | 메뉴로 원하는 섹션에 바로 이동하는 원페이지 스크롤 |
| 가격 표현 | 이 랜딩에는 요금제·가격 섹션을 넣지 않음 |
| 핵심 인상 | 믿을 만한 교사용 도구, 편안한 말투, 실제 제품이 선명히 보이는 화면 |
| 피할 표현 | “교사를 대신한다”, “자동으로 완성된다”, 검증되지 않은 절약 시간·정확도, 출시 예정·대기 신청 |

### 디자인 판단

채널웍스의 큰 한글 제목과 여백, Vrew의 실제 편집 화면 제시를 주된 축으로 삼는다. 서비스 특유의 따뜻함은 크림빛 배경, 연보라 영역, 뽀뽀의 작은 안내 장면으로 더한다. 첫 화면부터 제품의 사진·메모 입력 화면을 보여준다. 캐릭터가 제품을 가리거나 모든 섹션의 중심이 되지 않게 한다.

### 랜딩 기획의 네 가지 기준

| 기준 | 쌤씀에 적용한 결정 |
| --- | --- |
| 핵심 가치의 흐름 | **문제:** 사진·메모와 여러 보육 서류가 흩어져 기록을 시작하고 이어 쓰기 번거롭다 → **해결:** 사진 또는 메모로 원아별 초안을 시작하고 알림장→관찰일지, 보육일지→주제계획안으로 이어 쓴다 → **기대효과:** 빈 문서에서 시작하는 부담을 줄이고 선생님은 내용 확인·수정에 집중한다. 실제 절약 시간처럼 측정되지 않은 성과는 주장하지 않는다. |
| 주요 타깃 | 보육 기록 작성이 부담스러운 **어린이집·유치원 교사**. 영아반 담임의 사례와 화면으로 공감대를 만들되, 영아반 전용 서비스처럼 한정하지 않는다. |
| 방문자의 핵심 행동 | 제품 화면과 기록 흐름을 이해한 뒤 **‘쌤씀 체험하기’**를 눌러 가입 없는 체험 화면에 들어간다. 보조 행동은 상단 메뉴로 관심 섹션 바로 보기와 ‘어떻게 쓰는지 보기’다. |
| 섹션 순서·핵심 메시지 | 히어로(쉽게 시작) → 사용 방법(입력 흐름) → 핵심 기능 4개와 연결 기록(해결) → 추가 기능(확장) → 교사의 검토(신뢰) → 교사 설문(문제의 근거) → FAQ → 마지막 체험 CTA(기대효과와 행동). 긴 설명보다 제품 화면을 먼저 보여주고, 문제·해결·기대효과가 전체 페이지에서 이어지게 한다. |

## 2. 랜딩 구조와 실제 문구

상단 메뉴: **쌤씀 로고 | 사용 방법 | 주요 기능 | 더 많은 기능 | 교사 설문 | 자주 묻는 질문 | 쌤씀 체험하기**. 모든 메뉴는 같은 페이지의 해당 섹션 앵커로 이동한다. 로고는 맨 위로 이동한다. 스크롤 중에는 높이가 낮은 고정 헤더를 사용하고 앵커 위치는 헤더 높이만큼 여유를 둔다. 모바일에서는 간결한 메뉴 패널로 제공한다.

| 순서 | 섹션과 핵심 문구 | 화면·연출 | 행동 |
| --- | --- | --- | --- |
| 1 | **선생님의 오늘이, 기록의 초안이 되도록.** 사진이나 메모로 쉽게 시작하고, 이어지는 기록도 만들 수 있다는 설명 | 왼쪽 큰 제목과 두 버튼, 오른쪽에 Figma의 ‘오늘의 기록’ 입력 화면을 크게. 사진 썸네일과 메모가 보이게 구성 | 체험하기 / 사용 방법 보기 |
| 2 | **사진 한 장, 짧은 메모에서 시작해요.** | 사진 선택 또는 메모 입력 → 원아 선택 → 입력 내용 수정(선택) → 초안 생성. 스크롤 진행에 따라 같은 제품 창의 내용만 차분히 바뀌는 장면. 생성 뒤에는 초안을 교사가 확인·수정할 수 있음을 표시 | 주요 기능으로 이동 |
| 3 | **사진 첨부** · “오늘의 사진을 기록에 담아주세요.” / **알림장** · “원아별 하루 이야기를 초안으로.” | 사진 첨부 화면과 원아별 알림장 결과 화면을 각각 넓은 제품 캡처로 제시. ‘사진·메모 → 알림장’ 연결을 시각화 | 체험하기 |
| 4 | **관찰일지** · “알림장에서 관찰 기록으로 이어가세요.” / **보육일지** · “오늘의 활동을 일지 초안으로 정리하세요.” | 알림장 → 관찰일지, 사진·메모 → 보육일지 두 경로를 구별한다. 관찰일지의 내용·해석·지원 계획과 보육일지의 활동·평가 화면을 크게 제시 | 체험하기 |
| 5 | **기록을 넘어, 선생님의 하루에 이어지는 도구들** | 보육일지 → 주제계획안 연결을 먼저 보여준 뒤, 주간 계획안·월간 계획안·상담 준비와 답변·원아 메모·반과 원아 관리·원내 양식 설정·문체 선택·아뜰리에 제작을 모두 소개한다. 화면이 있는 기능은 Figma 데모를 사용하고, 없는 기능도 짧은 설명 카드로 빠짐없이 배치한다 | 체험하기 |
| 6 | **초안은 쌤씀이, 마지막 확인은 선생님이.** | 생성 → 원아별 확인 → 수정 → 완료 흐름. 사람이 검토한다는 신뢰 메시지. 데이터 보호·보관에 대한 구체적인 약속은 정책 확인 전 기재하지 않는다 | 사용 방법 보기 |
| 7 | **선생님이 기록에 쓰는 시간을 살펴봤어요.** | 교사 사전 설문의 맥락을 한 장면으로 설명. 필요하면 ‘107명 응답 / 지난주 근무시간 밖 업무 경험 86%’처럼 조사 대상·질문을 함께 적는다. 제품 사용 효과나 고객 후기로 보이게 하지 않는다 | 없음 |
| 8 | **자주 묻는 질문** | 사진·메모 중 하나만으로 시작할 수 있는지, 원아 선택, 초안 수정, 알림장→관찰일지, 체험 방법 등 실제 확인 가능한 4~6개. 가격 질문은 넣지 않는다 | 체험하기 |
| 9 | **기록의 가치는 지키고, 작성의 부담은 줄입니다.** | 연보라 바탕, 큰 제목, 제품 화면 일부와 작은 뽀뽀. 하나의 선명한 CTA | 쌤씀 체험하기 |

### 기록이 이어지는 두 경로

| 시작 | 첫 결과 | 이어서 만드는 기록 |
| --- | --- | --- |
| 사진 선택 또는 메모 입력 → 원아 선택 → 필요하면 입력 수정 | 알림장 초안 | 알림장 → 관찰일지 초안 |
| 사진 선택 또는 메모 입력 → 원아 선택 → 필요하면 입력 수정 | 보육일지 초안 | 보육일지 → 주제계획안 초안 |

첫 화면에서는 ‘쉽게 시작한다’를 가장 강조하고, 두 경로는 아래로 스크롤하며 이해하게 한다. 연결 화면의 버튼명과 변환 방식은 실제 제품 UI에 맞춘다.

### 핵심 기능 표현 규칙

- **사진 첨부**는 교사가 사진을 직접 선택해 첨부하는 흐름으로 표현한다. 얼굴 인식이나 자동 원아 분류를 이 기능에 섞어 설명하지 않는다.
- **알림장, 보육일지, 관찰일지**는 각각 독립된 섹션 또는 화면으로 드러낸다. 세 문서를 하나의 추상적인 ‘AI 기록’ 카드로 합치지 않는다. 주제계획안은 보육일지 다음 흐름에 둔다.
- 모든 결과 문구는 **초안 생성 → 교사 확인·수정**을 기본으로 한다. 실제 Figma의 화면 명칭과 버튼 흐름을 따르되, 최종 제품과 다른 표기는 배포 전에 수정한다.
- 추가 기능은 위 목록을 모두 발견할 수 있게 하되, 네 핵심 기능보다 시각적 우선순위를 낮춘다. 상세 명칭과 기능 설명은 실제 제품과 맞춰 게시한다.

## 3. 화면 구성

### 데스크톱

- 첫 화면은 텍스트 5/12, 제품 화면 7/12 정도의 비율. 제목 2~3줄, 설명 2~3줄, CTA 2개를 왼쪽에 둔다.
- 제품 캡처는 브라우저 모형 안에 무작정 축소하지 않는다. 화면의 일부를 확대·크롭해 사진, 입력창, 결과 영역을 읽을 수 있게 한다.
- 주요 기능 4개는 두 묶음으로 이어지는 긴 이야기처럼 배치하되, 각 기능의 제목과 캡처가 독립적으로 읽힌다.
- 뽀뽀는 히어로 가장자리, 전환 장면, 마지막 CTA에만 작은 크기로 사용한다. 기존 캐릭터 원본을 우선 사용하고 임의의 새 얼굴을 만들지 않는다.

### 모바일

- 제목 → 설명 → CTA → 제품 화면 순서. 버튼은 세로로 쌓고 한 손으로 누르기 편한 높이를 유지한다.
- 표 형태의 보육일지는 전체 표를 축소하지 않고 핵심 행을 보여주는 전용 모바일 크롭을 사용한다.
- 스크롤 연출이 꺼져도 사진·메모→알림장→관찰일지 및 사진·메모→보육일지→주제계획안의 두 경로가 정지 화면만으로 이해되게 한다.
- 모바일 고정 CTA는 첫 화면 이후에만 나타나고 마지막 CTA 섹션에서는 중복 노출하지 않는다. 메뉴 버튼으로 모든 주요 섹션에 바로 이동할 수 있게 한다.

## 4. 디자인 토큰

아래 값은 랜딩용 기준값이다. Figma와 코드에서 **같은 이름**을 사용한다.

### 색

| 토큰 | 값 | 사용 |
| --- | --- | --- |
| `brand/500` | `#8B63DA` | 브랜드 대표색, 큰 장식, 밝은 배경 위 강조 |
| `brand/600` | `#7549C2` | 기본 버튼·텍스트 링크. 흰 글자와 대비 약 6.0:1 |

| `brand/200` | `#CB98ED` | 일러스트·장식. 작은 본문 텍스트에는 사용하지 않음 |
| `brand/050` | `#F3ECFC` | 연보라 섹션·카드 배경 |
| `surface/base` | `#FFFFFF` | 카드·제품 화면 바탕 |
| `surface/warm` | `#FCFAF7` | 기본 페이지 배경 |
| `surface/cool` | `#F8F5FC` | 기능 구분 배경 |
| `ink/900` | `#1F1830` | 큰 제목·본문 주색 |
| `ink/600` | `#6A557F` | 보조 설명. 흰색 대비 약 6.5:1 |

원래 대표색 `#8B63DA` 위에 흰색 작은 글씨는 대비가 약 **4.29:1**이다. 따라서 작은 글씨가 들어가는 기본 버튼 배경은 `brand/600`을 사용한다. 브랜드색은 큰 제목의 일부, 면, 도형에 활용한다.

### 글꼴과 글자 크기

- 기본 글꼴: **Pretendard Variable**, 대체 `Apple SD Gothic Neo`, `Noto Sans KR`, 시스템 sans-serif. 실제 배포 시 웹폰트 로딩과 사용 조건을 확인한다.
- 숫자와 영문도 같은 글꼴로 통일. 제목은 700~800, 본문은 400~500, 버튼은 600~700.

| 스타일 | 데스크톱 | 모바일 | 용도 |
| --- | --- | --- | --- |
| `display` | 64px / 1.14 / -0.035em / 800 | 40px / 1.2 / -0.03em / 800 | 첫 화면 제목 |
| `h1` | 48px / 1.2 / -0.03em / 750 | 34px / 1.25 / -0.025em / 750 | 섹션 제목 |

| 카드 반경 | 20px, 큰 제품 화면 24px, 작은 태그 10px |
| 버튼 | 높이 56px(모바일 52px), 좌우 24px, 반경 14px, 최소 터치 영역 44px |
| 그림자 | 제품 화면에만 약하게 `0 20px 60px rgba(31,24,48,.10)`; 일반 카드는 경계선 중심 |
| 반응형 분기 | 모바일 `<768px`, 태블릿 `768~1023px`, 데스크톱 `≥1024px` |

### 컴포넌트 규칙

- **기본 버튼**: `brand/600` 바탕 + 흰 글씨. hover `brand/700`. 포커스 2px 외곽선과 2px 간격. 비활성 상태는 색만 낮추지 말고 실제 동작 상태와 함께 표시.
- **보조 버튼**: 흰색 바탕 + `ink/900` 글씨 + `border/default` 경계. hover에는 `surface/cool`.
- **기능 카드**: 작은 번호 또는 아이콘, 한 줄 제목, 2줄 이내 설명, 실제 화면 일부. 아이콘만으로 의미 전달하지 않는다.
- **제품 화면**: 같은 창 테두리·그림자·크롭 규칙을 사용. 개인정보가 담긴 실제 원아 사진과 이름은 쓰지 않고 승인된 데모 데이터로 교체.
- **FAQ**: 제목 전체가 클릭 가능한 아코디언, 열림 상태 표시와 키보드 조작 제공.

### 움직임과 접근성

- 스크롤 장면은 1곳만 주연으로 사용: 사진 또는 메모에서 두 기록 경로로 이어지는 흐름. 나머지는 200~350ms의 간단한 등장·상태 전환. 앵커 이동에도 움직임 감소 설정을 적용한다.
- `prefers-reduced-motion`에서는 이동·고정 스크롤 효과를 없애고 모든 단계의 정적 설명을 보여준다.
- 제목→설명→CTA→화면 순서가 시각·키보드·스크린리더 순서에서 일치하도록 한다. 포커스 표시, 이미지 대체 텍스트, 버튼 동사, 명확한 링크 목적을 제공한다.
- 본문 텍스트는 일반적으로 4.5:1 이상, 큰 텍스트와 UI 경계는 해당 역할의 대비를 검사한다. 장식 보라는 본문색으로 쓰지 않는다.

## 6. 제작 단계의 산출물과 확인점

1. Figma의 로고·뽀뽀·데모 화면을 원본 자료로 사용한다. **공개 가능한 데모 캡처**를 선정한다: 사진 첨부, 원아별 알림장, 당일 보육일지, 관찰일지. 화면 텍스트와 아동 정보는 데모 데이터로 정리한다.
2. 이 토큰으로 데스크톱 1440px, 모바일 390px의 첫 화면·4개 핵심 기능·마지막 CTA를 먼저 만든다. 이후 나머지 섹션을 같은 시스템으로 확장한다.
3. 실제 제품의 메뉴·기능명과 추가 기능 범위를 대조한다. **자동 사진 분류** 같은 별도 기능은 출시 제품에 실제 포함된 경우에만 독립적으로 소개한다. Figma에 없는 추가 기능은 제공 화면·문구를 확정해 카드에 반영한다.
4. `쌤씀 체험하기`의 가입 없는 체험 주소와 진입 방식을 확인한다. 아직 연결 주소가 없다면 코딩 단계에서는 설정값으로 분리하고 공개 전에 실제 체험 화면으로 연결한다. 가격 섹션은 만들지 않는다.
5. 모바일에서 핵심 4기능과 CTA가 빠짐없이 보이는지, 버튼·텍스트 대비, 키보드 조작, 화면 로딩을 확인한 뒤 공개한다.

**현재 남은 제품 정보:** 체험 화면 주소, 추가 기능의 실제 화면과 설명, 설문 표시 문구의 최종 확인, 운영 정책. 랜딩 구성과 디자인 시스템은 위 기준으로 진행한다.

## 7. 다른 AI 제작자에게 전달할 작업 지시

> **쌤씀의 완성된 서비스를 소개하는 반응형 원페이지 랜딩을 제작해 주세요.** 이 문서의 섹션 순서·카피·디자인 토큰·레퍼런스 적용 위치를 기준으로 구현합니다. 브랜드명은 쌤씀, 캐릭터는 뽀뽀입니다. 첫 화면에서 실제 제품 UI와 ‘선생님의 오늘이, 기록의 초안이 되도록.’을 함께 보여주세요. 사진 첨부·알림장·보육일지·관찰일지 네 기능은 각각 분명하게 보여주고, 알림장→관찰일지 및 보육일지→주제계획안 흐름도 표현하세요. 추가 기능은 문서의 목록을 모두 포함하되 핵심 기능보다 작은 위계로 배치합니다. 상단 메뉴는 같은 페이지 섹션으로 이동하고, 기본 CTA ‘쌤씀 체험하기’는 가입 없는 체험 페이지로 연결합니다. 체험 주소가 아직 없으면 단일 설정값으로 분리하고 임의의 가입·결제 페이지나 작동하지 않는 버튼으로 대체하지 마세요. 가격표·대기 신청·출시 예정 표현은 넣지 않습니다. Figma의 승인된 로고·뽀뽀·데모 화면을 우선 사용하고, 접근 권한이 없거나 원본 추출이 불가능하면 필요한 파일 목록을 명확히 알려주세요. 임의 생성한 실제 아동의 이름·사진, 검증되지 않은 성과 수치, 제품에 없는 기능 동작을 만들지 마세요. 데스크톱과 모바일에서 모두 읽기 쉽고, 키보드 접근·움직임 감소 설정도 지원해 주세요.

### 구현 후 확인할 항목

- [ ] 상단 메뉴에서 각 섹션으로 이동하고, 모바일 메뉴를 닫은 뒤에도 정상 작동한다.
- [ ] 사진 또는 메모로 시작하는 입력 흐름과 **두 기록 경로**가 한눈에 구별된다.
- [ ] 네 핵심 기능의 제품 화면과 제목이 각각 보이고, 추가 기능 목록도 빠짐없다.
- [ ] 390px 모바일에서 제목·버튼·제품 화면이 잘리지 않으며 보육일지 표가 읽힌다.
- [ ] 설문은 ‘교사 대상 사전 설문, 응답 107명’ 등 출처·모수를 함께 표기하고 서비스 사용 성과로 오인시키지 않는다.
- [ ] 체험 CTA는 실제 체험 화면 주소로 연결된다. 주소가 정해지기 전에는 공개하지 않는다.
- [ ] Figma 원본 사용 여부, 교체한 데모 데이터, 누락된 자산을 제작 결과와 함께 보고한다.
